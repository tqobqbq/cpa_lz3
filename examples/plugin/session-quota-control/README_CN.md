# Session 手动分配与 5 小时额度节流插件

## 构建和启用

在项目根目录执行：

```bash
bash examples/plugin/session-quota-control/build.sh
```

脚本会在 `bin/session-quota-control/` 生成服务器和插件，再将同一份插件发布到
`plugins/<系统>/<架构>/session-quota-control.so`（macOS 为 `.dylib`，Windows 为 `.dll`）。
每次构建成功都会同步更新两个目录里的插件。
需要 Go 1.26、CGO 和 C 编译器。必须使用新构建的服务器，原版服务器缺少本插件需要的接口。

将本目录的 [config.example.yaml](config.example.yaml) 合并到现有配置，保留其他配置项。
启用原生 `routing.session-affinity`、全局插件开关和本插件，然后在项目根目录启动：

```bash
./bin/session-quota-control/cli-proxy-api --config config.yaml
```

也可执行 `bash a.sh`，自动重新构建服务器和插件，再使用 `config.yaml` 启动。
额外的命令行参数会传递给服务器。

从管理界面的 **Session & quota control** 菜单进入，或直接访问：

```text
http://你的服务器地址/v0/resource/plugins/session-quota-control/dashboard
```

先在**同源的主管理界面**登录。插件只有一个页面，包含“会话调度”“Credential 管理”、
“访问控制”“用量统计与请求记录”和“Hub”五个标签页，共用连接；切换时保留筛选、分页、展开项和输入草稿，
只有当前标签页自动轮询。

嵌入主管理界面时，插件通过父页面直接使用当前已登录的管理连接发送请求，不依赖额外的
Cookie 衔接，也不要求重复输入 Management Key。服务器在返回 `/management.html` 时接入
当前前端的登录状态，主界面登录或退出后插件随之变化。不改写下载的前端文件，不向插件 iframe
传递明文密钥，也不在插件的 localStorage 或 sessionStorage 中保存密钥。

独立打开插件时，仍可使用加密的 HttpOnly 浏览器会话作为备用。

备用浏览器会话最长有效 12 小时；服务器重启、会话过期或管理密钥变更后失效。
嵌入页面仍直接使用主管理界面的当前有效连接，不受备用 Cookie 有效期影响。
主管理界面退出到登录页或触发未授权事件时，会清除浏览器会话。会话只可访问 v8 插件扩展接口
及逐插件配置，每次请求仍检查现有管理密钥和远程访问策略。
同源要求协议、主机和端口一致，不要混用 `localhost`、`127.0.0.1` 或不同域名。
外部部署的管理前端不能通过此衔接复用登录。连接成功后不显示登录提示块；只有鉴权失败时
才显示恢复连接入口及可展开的 Management Key 备用输入。

首次更新需要同时替换服务器和插件到 **0.3.2 或更新版本**，并刷新一次主管理界面。
打开页面即会在调度设置输入框中显示插件默认值，连接成功后替换为服务器当前配置。

### 主管理界面的额度同步

主管理页面已登录且可见时，每 2 秒读取一次 `GET /v8/management/credentials/quota-observations`，
返回页面或窗口重新获得焦点时立即读取。将 Codex 和 Claude 响应头中的额度快照，
通过原生凭证身份判断和窗口解析函数写入 Credential Management 使用的额度缓存。
按观测时间更新，旧快照不覆盖更新的主动查询结果；快照中没有的窗口保留已有值。
这些读取只访问服务器内存，不向上游查询额度。页面隐藏或退出登录后停止轮询。

0.4.0 起，额度与等待设置集中到“Credential 管理”标签。最新响应快照每 2 秒从主项目内存读取，
不向上游查询。显示所有返回的窗口，包括 5 小时、周、代码审查、模型专用及其他限额，
有点数余额时也会显示。上游返回已用比例时换算为剩余比例，例如已用 15% 显示剩余 85%；
未返回的数值保持未知。每个 credential 显示响应观测时间和各窗口重置时间，可展开全部
已保留的额度字段。请求详情仍保留当时计算等待使用的快照，显示刷新不会重算等待时间。

### 降智检测（0.5.0）

每个 Credential 行新增“降智检测”按钮，弹窗内可查看历史记录、计划中的检测，
点击“新增检测”选择模型、effort、检测项目和时间。默认：

- 模型 `gpt-6-astra`、effort `low`；模型名称可编辑，原样发送，须由所选凭证支持。
- 勾选“数字指纹”和“画鹈鹕”，分别立即执行、提交后 5 分钟执行，共 **4 项检测**。
- 每项数字指纹包含 3 道挑战，因此默认预计产生 8 次模型请求，失败重试可能增加请求数。

0.5.1 修正了默认模型名的拼写。已有检测记录保留原模型名，更新后请新增检测。

也可添加其他延后时间（1～1440 分钟），最多选择 8 个时间。

三项检测从 `cpa-plugin-codex-candy-eval` v0.4.2 移植：

- 糖果题完整保留原题及独立数字 `21` 的判分规则，不验证推导或最终结论。
- 数字指纹复制完整分类算法、36 道挑战、参考库及校准数据；每项随机抽 3 道。
  所选 effort 同样用于指纹请求。参考库不认识的模型名称或别名不判定“一致 / 不一致”，
  仍显示候选排名。概率只在参考库候选间比较。
- 画鹈鹕保留原版动画与多合一版。模型直接回复 HTML / SVG，由隔离的浏览器窗口渲染；
  不执行 Codex 工具，不修改工作区文件，也不自动给画面质量打分。

请求通过宿主绑定到所选 Credential，协议转换与最终 payload 规则仍由宿主处理。
无效回答、暂时性服务错误最多尝试 3 次；糖果题答错、凭证拒绝或限流不自动重试。
已建立的模型流不设时间超时，可在记录中手动取消。最多并行 4 项检测、6 次模型请求。

关闭弹窗或浏览器不会停止检测。任务与完整结果保存在独立的 `evaluation_db_path`
SQLite 数据库中，默认 `~/.cli-proxy-api/session-quota-control/evaluations.sqlite`，
不受用量统计开关影响。待执行任务在插件或服务器重启后保留原计划时间；到期后按并发
空位执行。正在执行时被中断的任务标记为“已中断”，不自动重复执行。
执行前会复查 Credential 是否仍存在且启用。每个 Credential 保留最近 100 项已结束
的检测，以及全部待执行、执行中的检测。

算法来源、固定版本及 MIT 许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

### Hub 渠道管理（0.6.0）

打开插件的 **Hub** 标签，或在页面地址后添加 `#hub`。
填写 Authorization、KEY_ID、检测模型和 Effort 后保存；接口地址、协议、代理、
Project ID、可选 Cookie、筛选关键词和已选渠道 ID 也会保存，刷新或重启后可复用。
Authorization 支持裸 Token 或 `Bearer …`，保存后不向页面返回明文；留空保留原值，
需要删除时勾选清除后保存。模型调用密钥由服务端按 KEY_ID 读取，不写入检测记录。

三个操作独立：

1. **查找免费渠道**：分页读取公开且启用的渠道，排除已知收费或没有有效价格信息的渠道。
   查找不需要 KEY_ID 或检测模型，不修改绑定，也不调用模型。可以按模型关键词筛选列表。
2. **检测所选渠道**：使用勾选或手填的渠道 ID；也可先点击“读取 Key 当前渠道”，
   不必执行免费渠道查找。每批 1～100 个渠道，依次临时绑定到指定 Key；清除标签、动态路由和
   fallback 渠道后回读确认，等待 500ms 传播，再运行插件现有降智检测的数字指纹。
   每个渠道 3 道挑战，沿用原参考库、校准、模型别名及重试规则，默认 Effort 为 `low`。
3. **应用通过渠道**：检测结束后手动点击。仅应用 3 道挑战完整有效、且模型匹配的渠道，
   未知模型、样本不足、模型不一致及失败不算通过。写回采用该 Key 的显式渠道绑定，
   保留配额、模型映射、Provider 限制及非活动 Profile。

Hub 模型请求直接使用该 Key 调用配置的 Base URL。自动协议对包含 `claude` 的模型使用
Messages，其余使用 Responses；也可以手动选择。Messages 将 `minimal` 映射为 `low`、
`xhigh` 映射为 `max`。请求不执行模型返回的工具，不设置已建立模型流的时间限制。
详情复用现有降智检测视图，显示数字挑战、识别结果、候选概率和用量。

检测开始前保存原 Profile，正常结束、失败或手动取消后恢复；关闭页面不停止后台任务。
绑定操作前写入恢复记录；服务重启、网络故障导致恢复未完成时，页面提供“恢复 / 核对绑定”。
如果 Key 被外部操作修改，不覆盖这些修改，需先在 Hub 恢复页面显示的原配置。
恢复完成前阻止新的绑定操作，仍可更新 Authorization、Cookie 和代理。
同一时间执行一个 Hub 操作，防止切换绑定时混用渠道。

配置、最近 10 批检测、渠道列表和恢复记录保存在 `evaluation_db_path` 后追加
`.hub.json` 的文件中，默认 `~/.cli-proxy-api/session-quota-control/evaluations.sqlite.hub.json`。
此文件含 Authorization / Cookie，权限为 `0600`；与用量采集开关无关。
不依赖本机的独立 ModelTrace 项目。

## Credential 与 API key 双向访问控制（0.7.0）

此版本要求同时重新构建服务器与插件，宿主 RPC schema 至少为 8。

在“访问控制”标签页按 Credential 或 API key 编辑名单，也可点击 Credential 行的
“访问控制”快捷入口。限制针对具体上游账号，以页面显示的 `auth_index` 关联，
同一 Provider 的不同账号可以设置不同权限。API key 指客户端访问 CPA 的密钥，
在管理页面完整显示；名单配置保存原始 key，不做脱敏或指纹替代。

每侧只能选择**黑名单**或**白名单**，默认是**空黑名单，允许全部**。
黑名单拒绝名单中的对象；白名单只允许名单中的对象，空白名单拒绝全部。
Credential 侧列出 API key，API key 侧列出 Credential 的 `auth_index`，两侧都允许
才能调用，一侧的允许不能覆盖另一侧的拒绝。页面提供搜索、多选和包含未保存草稿的
最终授权预览；账号启用状态、模型支持、冷却和额度仍由原生调度器判断。

规则保存在 `plugins.configs.session-quota-control.access_control` 的
`credential_rules` 和 `api_key_rules`，每条规则包含 `mode` 与 `entries`。
参见 [config.example.yaml](config.example.yaml)。保存后热更新，刷新不会覆盖未保存的
草稿。删除账号或 key 不自动删除名单引用，页面保留这些条目供核对；轮换 key 后按新 key
配置权限，重新排列 key 不影响原有规则。

本地候选在优先级、轮询、粘性绑定及手动分配前过滤；故障切换、同账号刷新重试、
普通请求、流式请求、WebSocket 模型请求和 token 计数使用相同限制。
手动分配队列按 API key 隔离；等待期间权限收紧会结束对应等待，发往上游前再次复查。
已经发出的请求继续完成。全部候选被名单排除时返回
`403 credential_access_denied`；过滤器异常返回 `503 credential_access_filter_failed`，
不会回退到未过滤的候选。插件自身由管理功能发起、且没有客户端 key 的降智检测
保留管理权限；客户端发起的嵌套模型请求仍检查名单。

## 功能一：新 session 等待手动分配

原生 Session Affinity 先检查显式 session、父子会话和内容匹配。
没有可复用绑定时，请求会进入页面的待分配列表，默认等待 **60 秒**。
可以选择该请求支持的 credential，也可以点击“自动调度”立即继续。
到期未选择时，继续执行项目原来的优先级和轮询逻辑。

如果原本手动指定的 credential 执行失败，需要改用其他 credential，请求会重新进入手动分配。
后续复用该手动绑定的请求，以及继承该手动绑定的子会话，也遵循此规则。页面会显示原来手动
指定的 credential。等待超时或点击“自动调度”会将新绑定交给原生调度；之后自动选择的
credential 再失败时，继续自动故障切换，不重复等待。关闭手动分配开关也会释放重选请求。

手动选择通过项目原生缓存建立粘性绑定；已有可复用绑定的请求直接通过。
候选项直接来自原生 provider、模型支持、访问权限和可用状态筛选后的集合，并排除本次请求
已经尝试过的 credential。手动选择可以跨优先级；超时后的原生调度仍使用最高可用优先级。
选择完成后会重新检查 credential 的可用性和模型支持；如果刚选的 credential 已不可用且
仍有其他候选项，会再次等待手动选择。
关闭手动分配开关会释放正在等待的请求。客户端取消请求时也会清理队列。
完全没有可用会话标识的请求仍可单独分配；后续粘性需要客户端标识或项目能够推断出的会话身份。

### 查看粘性判断字段

在待分配行展开“查看全部判断字段”，可查看原生选择器使用的 session/thread 和父会话标识、
相关请求头与 body 标识字段、解析结果、WebSocket 连接及派生身份、provider、原始模型与去掉
effort 后缀的模型、实际缓存键与绑定状态、TTL、子会话继承开关、失败重绑策略，以及内容匹配的
namespace 和指纹。输入映射中仅列出该请求实际提供的身份字段。

页面还保留最近 50 次已结束的待分配诊断及手动指定、自动放行、超时或中断结果，便于对照重复
进入待分配的 Codex 请求。这些记录保存在进程内存中，重启后清空；正常命中原生绑定的请求不会
产生待分配诊断。展开详情和页面刷新不会改变会话绑定或读取上游额度。诊断数据使用现有管理鉴权，
不包含 Authorization 等登录凭证或完整消息正文。

## 功能二：每次请求只计算一次等待时间

选定 credential 后，自动模式只读取一次主项目现有的 5 小时额度快照，计算一次等待时间，
然后通过一个计时器等待。节流流程在等待期间不再读取额度或重算时间；客户端取消时立即结束等待。
普通请求、流式请求和经过请求拦截器的 WebSocket 请求采用同一逻辑。

同一个 credential 的多个请求各自使用独立计时器，并行等待。例如同时到达的 3 个请求都固定
等待 30 秒，会在约 30 秒后一起继续，不会依次等待 30、60、90 秒。历史平均并发影响自动估算，
不会将计时器改为串行队列，也不会自动错开唤醒时间。

```text
等待时间 = 距离重置的时间 × min(1, 模型平均消耗 × 历史平均并发 ÷ 可用剩余额度)
可用剩余额度 = 快照中的剩余比例 − 安全余量
```

剩余额度不足或用尽时，自动等待最多到本次快照的重置时间。
缺少有效的 5 小时观测时，自动模式不等待。插件和页面均不主动轮询上游额度接口。
调度页面独立显示服务器缓存的最新响应额度；周及其他窗口用于展示，不参与 5 小时等待公式。

模型消耗采用当前进程内**全部 credential 的同一 provider、上游模型最近 100 个可归因样本的滑动平均**。
从模型标识中移除 reasoning 后缀，token 数、请求长度、effort、输出上限、service tier 等均不参与计算。
模型没有样本时，默认预计每次消耗 1% 额度，可在页面调整。

请求完成后，根据响应中的额度比例变化学习模型消耗。
某段观测期间同一模型完成 k 次请求、额度增加 d，就以 d/k 作为每次请求的消耗样本。
百分比没有变化时先累计请求数；不同模型混杂、无法归因的区间跳过。
额度重置、重复和乱序的记录不会被当作正常消耗样本。

并发量采用**该 credential 过去 5 分钟内未完成请求数量的时间加权平均**，包含正在等待的请求，
最低按 1 估计。滑动样本数和并发统计时间都可以在页面修改。

## 每个 credential 的固定等待和上限

在“Credential 管理”标签中点击对应行的“等待设置”，支持分别保存：

- **等待上限**：留空不限制；填写 10 就将等待截断到最多 10 秒，填 0 则立即放行。
- **固定等待**：留空自动估算；填写 30 就直接等待 30 秒，不读取额度、不计算模型消耗或并发；填 0 则立即放行。

上限同时约束自动模式和固定模式。例如固定 30 秒、上限 10 秒，实际等待 10 秒。
设置单位为整秒，范围 0–86400。修改对后续请求生效，已开始的计时不改变。
关闭全局额度节流开关会让后续请求跳过自动和固定等待。

也可以按页面显示的稳定 auth_index 写入 YAML：

```yaml
credential_waits:
  "0123456789abcdef":
    max_wait_seconds: 120
    fixed_wait_seconds: null
  "fedcba9876543210":
    max_wait_seconds: 60
    fixed_wait_seconds: 30
```

固定时间和上限可能缩短自动估算的等待；历史平均和快照也存在误差，无法保证绝对不触达上游限额。

## 用量统计与请求记录

在插件内点击 **用量统计与请求记录** 标签，使用同一个页面和连接查看统计。
主项目插件菜单只保留 **Session & quota control** 一个入口。也可以直接打开统计标签：

```text
/v0/resource/plugins/session-quota-control/dashboard#usage
```

旧的 `/report` 地址仍可访问，会打开同一个页面并选中统计标签。

实现借鉴 CPA Usage Report v0.3.1 的 SQLite 存储、日期聚合和 Token 口径，
并扩展了本插件的等待记录；授权声明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
无需另装 usage-report 或运行独立统计服务。

统计页提供请求数、完成成功率、Token 总量、缓存率、API 单价与参考费用、首字延迟、含首字与不含首字两种 TPS，
以及 Token/等待趋势，支持日期、
模型、Provider、结果和搜索筛选，并按模型、上游 Provider、上游 Credential、下游明文 API Key 展示分布和分页明细。
展开请求可查看：

- 每次手动分配或错误后重选的实际等待、分配结果及超时回退。
- 每次 credential 选择的 5h 计划等待和实际等待，以及计算原因、模型消耗、并发估计和计算时使用的额度快照。
- 每次上游调用的模型、credential、Token、耗时、首 Token 延迟及成功/失败。
- 执行前取消或终止的请求，即使它没有产生 Token 用量。

请求列表通过状态标签、同列 Token 数量和分项耗时展示摘要，支持每页 25 / 50 / 100 条。
详情分为「请求概览」「单价 / 费用」「执行时间线」「原始数据」：时间线按事件开始时间串联手动分配、
Credential 选择及上游调用，失败调用自动展开；请求、Trace、Session、Credential ID 和 JSON 均可复制。
支持深浅色主题、窄屏及键盘切换。信息层次借鉴
[cpa-usage-stats](https://github.com/tom2almighty/cpa-usage-stats)、
[CPA Usage Statistics](https://github.com/Oniokey/CPAUsageStatistics) 与
[CPA Usage Report](https://github.com/andyWang1688/cpa-usage)，沿用本插件的请求关联及统计口径。

用量趋势可切换 **Token 用量 / 请求量 / 参考费用 / 等待时间**，跟随当前筛选条件统计全部分页数据。
支持按服务器时区的小时、天、月聚合；空闲时段补零，未来时段不显示，当前时段为尚未结束的累计值。
小时粒度保留时区偏移，夏令时切换不会合并重复小时。悬停、点击或聚焦图表后使用左右方向键可查看精确时段数据，
缓存数量和缓存率仅在文字明细中展示。费用曲线只计已估价金额，空心点标出含待定调用的时段；完全未定价时断开曲线，不当作免费。
请求及其全部重试按请求开始时间归入同一时段；选择「今天」默认切换为小时粒度。单次最多 5,000 个时段，超出时需缩短范围或改用天、月粒度。

请求列表、概览及每次执行显示最终出站档位：**Standard / Fast / Ultra-fast / Flex / Auto**，未知值保留原文。
宿主在 HTTP 发送前或 WebSocket payload 规则完成后采集 `outbound_service_tier`；过滤 `service_tier` 后记为 Auto，覆盖规则则记录覆盖后的值。
客户端原始 `service_tier` 与上游响应 `service_tier` 分别保留在详情中。历史未采集最终出站档位的记录会明确标注，不根据当前配置补推。
费用优先使用可确认的响应档位；Codex OAuth 响应的 default/auto 视为未确认，此时使用最终出站档位估价。
历史记录没有出站档位时沿用客户端档位估价并标明来源。
每次重试按自己的档位计算，费用同步进入汇总、用量分布和趋势图。

`service_prices.json` 保存 [OpenAI 官方文本 API 价格快照](https://developers.openai.com/api/docs/pricing)，覆盖 27 个模型及 42 组 Fast / Ultrafast / Flex 单价，
与上下文长度一起确定输入、缓存和输出价格，不使用统一倍率。其标准价覆盖 `prices.json` 中同名模型，其他模型仍使用 models.dev 快照。
缺少对应档位或上下文单价时显示待定。上游未返回档位时，按明确出站档位估价并注明；历史未记录或 Auto 未确认时，
使用明确标注的 Standard 基准参考价，汇总显示速度档位未确认的调用数。历史缺失字段无法还原。
OpenAI 缓存写入按 30 分钟参考价，当前计数未区分 12 小时写入；费用为 API 参考费用，不套用订阅额度或购买点数的倍率。

Effort 与速度独立，Effort 不直接乘单价。Codex 的 Ultra 是允许主动调用子代理的客户端模式，并非 Ultra-fast 速度档位。
客户端的 `X-Codex-Turn-Metadata` 可能包含 `reasoning_effort`，但不能保证响应 Header 会回显，也不能据此判断上游实际 Effort。
本页面仍展示宿主上报的实际执行 Effort。

请求明细和用量分布的 Token 分项都集中在同一列，按文字标签显示输入、净输入、缓存读取、缓存写入、输出及推理，
不画 Token 构成条；输入已包含缓存读写，输出已包含推理，子项不重复相加。
模型信息同时显示 **Effort** 和 **上游响应模型**，取最终 Credential 的最近一次调用记录；时间线保留每次重试自己的值。
两项均来自宿主上报，不从请求模型名或思考后缀猜测。历史记录或上游未提供时显示「未记录」，搜索支持这两个字段。

同一个请求用独立的生命周期 UUID 关联，重试只算一条请求；各次上游调用、Token 和等待
累计在这条请求下面，不通过 session ID 或短 Trace ID 猜测归属。未经过生命周期处理器的
执行以 `execution:` 开头单独显示，没有对应的手动或额度等待记录。

“手动分配等待”是从进入待分配到人工选择、自动放行、超时或取消的实际累计时间，包含错误后重选。
“5h 节流计划 / 实际”分别是应用固定等待和上限后确定的节流时长之和、计时器真正等待的时间之和。
5h 指额度窗口，不是每次等待 5 小时；重试时各次选择的等待累计。
进行中的请求在刷新时计入正在发生的等待时长；请求结束后仍缺少计时结果的部分显示为未知。
请求明细将 5h 实际、计划等待及发生过的手动分配等待合并展示在「等待时间」单元格；详情及汇总保留完整手动分配记录。
请求列表独立展示「来源 API Key / IP」和「上游 Provider / Credential」。API Key 直接保存并展示明文，
详情可复制完整 Key；搜索支持明文 Key 和 IP。旧版只保存了哈希的记录标为「历史匿名标识（无法还原）」，
缺失 IP 显示「未采集」。
计划等待 60 秒、在第 10 秒取消时，实际记录约 10 秒。统计页只读已有记录，不重新计算等待、
不额外刷新额度，也不消费原生用量队列。执行耗时不含执行前等待；总耗时覆盖服务内模型请求
生命周期，包含调度和重试，并非客户端网络总延迟。

**上游**指向哪个 Provider / Credential 请求模型；**下游**指哪个客户端使用哪个 API Key 请求本服务。
Provider / Credential 分组按各次实际调用归集；API Key 分组按请求来源归集，同一请求重试只计一次，
Token 与参考费用累计该请求的全部调用。来源 Key 从认证上下文取得，不读取可能已被替换的上游 Authorization；
IP 使用宿主现有的可信代理解析结果，缺失时回退直连 IP，不自行信任转发头。执行前取消也保留来源。
Token 使用统一分项口径，避免重复计入 Claude 缓存或 Gemini 推理。

- **缓存读取率** = 缓存读取 Token ÷ 总输入 Token；总输入包含缓存读写，汇总先累加再相除。
- **首字延迟**：成功调用中大于 0 且不超过执行耗时的 TTFT，从上游调用开始计时。
- **TPS（不含首字）** = 输出 Token ÷（上游执行耗时 − 首字耗时）。
- **TPS（含首字）** = 输出 Token ÷ 上游执行耗时。汇总卡片、各维度分组、请求列表及调用详情同时展示两项；
  两者均不包含执行前的调度等待。缺少 TTFT 时，不含首字 TPS 显示未知，含首字 TPS 可在执行耗时和输出有效时计算。
- TPS 只统计成功且用量、计时有效的调用；先累加有效输出 Token 和对应时长，再相除。
  输出包含推理 Token；缺失计时和用量显示未知，不按 0 处理。

API 价格使用随插件打包的 [models.dev](https://models.dev/api.json) 官方供应商文本模型快照，当前包含 235 条模型记录，
展示输入、输出、缓存读写的 **USD / 百万 Token** 单价、快照日期及参考费用，支持快照中的上下文长度阶梯。
只匹配明确模型 ID（可去除已知供应商前缀与思考后缀）；未知别名、缺失单价或不完整 usage 保留为未定价/待定。
快照不会运行时自动更新；历史记录也使用该快照估算，并非请求发生时的历史价格。
费用对应模型与速度档位的文本 API 单价，不代表套餐/OAuth 实扣、转售价格、批处理折扣或图片、音频、工具收费。
不同分组是同一批用量的不同观察维度，不应相加。费用「待定」表示有调用因模型未匹配单价、
适用单价缺失、缺少可计费用量或 Token 分项不完整而无法估价，页面展示具体原因及调用次数。
例如 `$0.12 + 待定（2 次）` 只代表已估价部分合计 $0.12，另外两次调用未计入，并非免费；
失败或重试调用未提供用量时也可能待定。

参考项目中，`cpa-usage-stats` 的单条与汇总 TPS 排除首字，但图表及分组存在使用总耗时的口径；
CPA Usage Statistics 主要展示 TTFT 等时延，CPA Usage Report v0.3.1 保存 TTFT 但前端未展示 TTFT/TPS。

默认启用统计，数据库位于 `~/.cli-proxy-api/session-quota-control/usage.sqlite`，可在统计页修改：

```yaml
usage_report_enabled: true
usage_db_path: "~/.cli-proxy-api/session-quota-control/usage.sqlite"
```

普通重启保留记录；上次运行遗留的进行中请求显示为服务中断，未完成的计时显示为未知。
启用功能前未记录的等待无法补回。数据持续保留，关闭采集不会删除数据库；修改路径后查看的是
另一个数据库。存储异常会显示在页面上，不阻止模型请求。数据库保存明文客户端 API Key、IP、session 和 credential 标识，
不存请求/响应正文和响应头；与独立 usage-report 插件的数据库分开。

主项目传递生命周期标识、统一 Token 分项，以及认证后的来源 API Key 和服务端解析的 IP。
需要同时构建并运行配套服务器和插件；新来源字段从更新后的请求开始采集，旧记录无法补回。

## 使用范围

支持本机原生调度。Home 模式由 Home 决定 credential，不使用这里新增的本地等待入口。
独立的调度插件也可能优先接管路由；使用手动 session 分配时，应让原生 Session Affinity 负责选择。

配置通过正常的 v8 配置接口保存并热更新。待分配记录、模型平均和并发历史保存在当前进程内存中，
重启后清空；新增的用量与等待记录保存在 SQLite 中。多个节点之间不共享统计。
旧的 token 估算、预留系数和最大并发配置已停用。

完整参数、算法和接口说明见 [README.md](README.md)。
